# Day26 学习记录：生成器异常注入与资源清理

## 一、学习目标

理解生成器的 `throw()` 方法，掌握异常注入、异常捕获、恢复执行，以及 `finally` 在生成器生命周期中的作用。

## 二、核心知识点

### 1. `generator.throw()`

- 向生成器当前暂停的位置注入指定异常。
- 异常可以由生成器内部的 `try-except` 捕获。
- 如果异常被捕获且生成器继续执行到下一个 `yield`，`throw()` 可以返回该 `yield` 的值。
- 如果异常没有被捕获，异常会传播到调用方。

### 2. `generator.close()`

- 请求生成器结束。
- 通过 `GeneratorExit` 触发生成器的退出流程。
- 正常处理关闭请求时，`close()` 返回 `None`。
- 生成器退出时，相应的 `finally` 清理逻辑会执行。

### 3. `try-except-finally` 的结构设计

- 内层 `try-except`：处理每条记录可能出现的异常。
- 外层 `try-finally`：负责整个生成器的清理工作。
- `finally` 的位置决定清理逻辑的作用范围。

## 三、实践内容

实现 `read_records(records)`：

1. 使用 `yield` 逐条返回记录。
2. 使用 `throw(ValueError(...))` 验证异常注入。
3. 捕获异常后继续读取后续记录。
4. 将 `finally` 放在循环外部。
5. 使用 `close()` 验证生成器提前退出时的清理行为。

测试数据：`[10, 20, 30]`

## 四、理解检查

1. `throw()` 用于向生成器注入异常，`close()` 用于请求生成器结束。
2. `finally` 放在循环外部，可以在整个生成器退出时执行清理逻辑，避免每轮循环都执行清理。
3. `throw()` 可以返回后续 `yield` 的值，而 `close()` 正常完成时返回 `None`。
4. 调用 `close()` 后，生成器不再继续正常读取后续记录。
