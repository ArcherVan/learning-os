# Day29 学习记录：unittest 单元测试

## 一、今日学习目标

- 学习使用 Python 内置的 `unittest` 编写单元测试。
- 掌握 `unittest.TestCase`、`assertTrue()` 和 `assertFalse()` 的基本用法。
- 理解边界值测试以及测试方法命名的要求。
- 通过故意修改源代码，验证测试能否发现逻辑错误。

## 二、今日完成内容

### 1. 编写单元测试

为 `is_pass(score)` 函数编写了三个测试：

- 输入 60，验证及格边界。
- 输入 59，验证不及格情况。
- 输入 80，验证普通及格情况。

使用 `unittest.TestCase` 组织测试，并通过 `unittest.main()` 启动测试。

### 2. 理解测试方法的命名

同一个测试类中的测试方法必须使用不同的名称。若两个方法同名，后面的定义会覆盖前面的定义，导致预期的测试没有被执行。

### 3. 验证测试能否发现逻辑错误

将 `score >= 60` 临时修改为 `score > 60`。

实验结果表明：

- 60 分测试失败，因为实际结果为 `False`，与 `assertTrue()` 的预期不符。
- 59 分测试通过，因为实际结果为 `False`，符合 `assertFalse()` 的预期。
- 80 分测试通过，因为实际结果为 `True`，符合 `assertTrue()` 的预期。

恢复正确的判断条件后，重新运行测试，三个测试全部通过。

## 三、关键知识点

1. 单元测试通过断言自动检查实际结果是否符合预期。
2. 边界值测试有助于发现条件判断中的逻辑错误。
3. 源代码存在缺陷时，不一定所有测试都会失败。
4. 测试失败可能源于源代码逻辑、测试预期或测试数据，需要结合失败信息进行诊断。
5. 测试全部通过只能说明当前测试覆盖的行为符合预期，不能证明程序不存在所有缺陷。
