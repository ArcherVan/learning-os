# Day24 学习记录：生成器资源清理

## 一、今日学习内容

1. 学习生成器的 `close()` 方法。
2. 理解 `finally` 在生成器清理过程中的作用。
3. 理解 `GeneratorExit` 与生成器关闭的关系。
4. 测试生成器正常结束、提前关闭和异常退出时的行为。

## 二、代码练习

实现 `read_records(records)`，使用 `yield` 逐条返回数据，并在 `finally` 中输出资源清理信息。

## 三、测试记录

- 场景 A：完整遍历生成器。
- 场景 B：只获取一条数据后调用 `close()`。
- 场景 C：处理数据时抛出 `ValueError`。

## 四、关键理解

1. `yield` 暂停生成器的执行，并将数据返回给调用方。
2. 对已经启动的生成器调用 `close()`，可以触发其清理逻辑。
3. 生成器在执行过程中发生异常并退出时，`finally` 会执行。
4. 异常传播到调用方之前，生成器会先执行 `finally` 中的清理代码。

## 五、需要继续巩固的内容

区分生成器内部异常、调用方异常，以及 `close()` 与 `GeneratorExit` 的执行机制。
