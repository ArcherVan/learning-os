# Day32 学习记录：dataclasses 与数据模型

## 一、今日学习内容

1. 使用 `@dataclass` 自动生成 `__init__()`、`__repr__()` 等常见方法，减少重复的样板代码。
2. 理解类型注解的作用：`task_id: int` 不会自动进行运行时类型校验。
3. 使用 `field(default_factory=list)` 为每个实例创建独立的默认列表。
4. 使用 `__post_init__()` 在对象初始化后执行数据校验。
5. 区分 `is` 和 `==`：
   - `is` 判断两个变量是否引用同一个对象。
   - `==` 判断两个对象的值是否相等。

## 二、实践任务

实现 `Task` 数据模型，包含任务编号、任务标题和标签列表。

- 任务编号小于 1 时抛出 `ValueError`。
- 任务标题为空或仅包含空白字符时抛出 `ValueError`。
- 使用 `default_factory=list` 保证不同实例的标签列表相互独立。

## 三、验证结果

已验证：

- 合法任务可以创建。
- 编号为 0 时触发 `ValueError`。
- 两个任务的标签列表互不影响。
- `task1.tags is task2.tags` 的结果为 `False`。

待补充验证：

- 空白标题是否触发 `ValueError`。

## 四、学习总结

理解了 dataclass 的基本机制、可变默认值的处理方式，以及对象初始化阶段的数据校验。掌握了通过 `default_factory` 避免多个实例共享可变列表的问题。
