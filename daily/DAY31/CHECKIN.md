# Day31 学习记录：unittest 测试组织与缺陷验证

## 一、今日学习内容

1. 将不同测试场景拆分为独立的测试方法。
2. 使用 `assertRaises(ValueError)` 验证异常行为。
3. 理解 `FAIL` 和 `ERROR` 的区别。
4. 通过人为引入业务缺陷，验证测试能否发现问题。

## 二、测试组织

将及格、 不及格和非法成绩分别放在独立的测试方法中：

- `test_pass()`：验证 60 分及格。
- `test_fail()`：验证 59 分不及格。
- `test_invalid_score()`：验证 101 分触发 `ValueError`。

## 三、FAIL 与 ERROR

- `FAIL`：代码正常执行，但断言结果不符合预期。
- `ERROR`：测试执行过程中发生未被预期或处理的异常。

## 四、缺陷验证实验

将业务代码中的 `score >= 60` 临时修改为 `score > 60`。

测试发现 `test_pass()` 失败，报告显示：

`AssertionError: False is not true`

原因是 60 分被错误地判定为不及格。

实验后将代码恢复为 `score >= 60`，并重新运行测试，确认所有测试通过。

## 五、今日总结

理解了独立测试方法的作用，能够区分断言失败和执行异常，并通过人为引入缺陷验证测试的有效性。

继续学习测试用例覆盖、边界场景设计，以及如何让测试更可靠地发现业务缺陷。
