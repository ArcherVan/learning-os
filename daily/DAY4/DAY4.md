# Day 4 — 异常处理、函数职责与小项目

## 今日目标

把 Day 3 已练过的模块、`import` 和程序入口继续用于一个独立的小程序，同时进一步巩固 `try/except`、函数职责和字典频次统计。

完成后应能：

- 说清楚 `try/except`、`ValueError` 和 `FileNotFoundError` 的作用；
- 能根据职责拆分函数，而不是把所有逻辑写进一个函数；
- 能用字典独立完成频次统计；
- 能把“文本分析”和“用户交互”放进不同文件；
- 能用边界数据验证程序，而不只验证正常输入。

## 练习顺序

### 1. 热身：异常处理

不运行代码，先说明下面代码可能发生什么，以及为什么：

```python
try:
    score = int(input("请输入成绩："))
except ValueError:
    print("输入必须是整数")
```

分别讨论：

- 输入 `85`；
- 输入 `abc`；
- 为什么这里捕获的是 `ValueError`；
- 为什么不直接使用 `except:`。

### 2. 核心：字典频次统计

给定：

```python
words = ["apple", "banana", "apple", "orange", "banana", "apple"]
```

使用普通 `dict` 统计每个单词出现的次数。

最终结果应包含：

```text
apple: 3
banana: 2
orange: 1
```

不要使用 `collections.Counter`。

然后思考：

- 第一次遇到一个单词时应该怎么处理；
- 再次遇到同一个单词时应该怎么处理；
- 为什么需要判断这个单词是否已经存在于字典中。

### 3. 小项目：单词频率分析器

创建三个文件：

- `analyzer.py`：只放文本分析和统计函数；
- `main.py`：只负责读取用户输入、调用函数、展示结果；
- `data.txt`：用于测试的文本文件。

`data.txt` 可以使用：

```text
python java python
c python java
linux git python
```

在 `analyzer.py` 中独立实现文本处理和频次统计。

在 `main.py` 中：

1. 让用户输入文件名；
2. 文件不存在时捕获 `FileNotFoundError`，提示后重新输入；
3. 调用分析函数；
4. 输出每个单词出现的次数；
5. 输出总单词数；
6. 输出出现次数最多的单词。

函数的具体名称和参数由自己设计。

### 4. 函数职责检查

完成后检查自己的代码：

- 哪个函数负责读取文件？
- 哪个函数负责统计频次？
- 哪个函数负责输出？
- 用户交互是否和数据处理分开？
- 如果某个函数同时负责很多事情，是否可以继续拆分？

不要为了“函数多”而拆分，重点是职责清晰。

### 5. 验证

至少验证以下情况：

- 正常文本；
- 空文件；
- 不存在的文件；
- 只有一个单词；
- 同一个单词重复出现；
- 两个单词出现次数相同。

## 完成标准

- `analyzer.py` 被导入时不主动要求输入或打印程序结果；
- `main.py` 可以独立运行；
- `ValueError` 和 `FileNotFoundError` 能被正确处理；
- 能独立完成字典频次统计；
- 空文件、重复单词和并列最高频率都有合理结果；
- 能用自己的话解释每个主要函数负责什么；
- 能用自己的话解释为什么要把分析逻辑和用户交互拆开。
